# Threat Model — V1 Licensing, Activation, Leases

Method: STRIDE over the trust boundaries in
[01-system-context](../architecture/01-system-context.md). Each mitigation names
the automated test that proves it. A threat without a test is an open risk and
is listed in §4. Re-run this review whenever a trust boundary changes
(ADR required).

Test shorthand: **LIC** = `packages/licensing/test/activation.test.ts`,
**POL** = `packages/licensing/test/policy.test.ts`,
**SDK** = `packages/sdk-core/test/lease-verifier.test.ts`,
**VEC** = `packages/sdk-core/test/vectors.test.ts`,
**JWS** = `packages/crypto/test/jws.test.ts`,
**SEC** = `tests/security/tenant-and-privilege.test.ts`,
**API** = `services/platform-api/test/api.test.ts`,
**DB** = `services/platform-api/test/db/migration.db.test.ts`,
**E2E** = `tests/integration/slice.e2e.test.ts`.

## 1. Assets

| Asset                       | Why it matters                                        |
| --------------------------- | ----------------------------------------------------- |
| License-signing private key | Forging leases = unlimited free use for every product |
| License keys (plaintext)    | Pre-authorization material for activation             |
| Customer data & documents   | Must never be lost/locked due to a licensing failure  |
| Org/tenant data             | Cross-tenant leakage                                  |
| Audit log                   | Non-repudiation, incident forensics                   |
| Session tokens, passwords   | Account takeover                                      |

## 2. Actors

Anonymous internet user · Authenticated customer (any org) · Org admin ·
Malicious customer (cracker/pirate) · Compromised client machine · Network
attacker (post-TLS: replay only) · Insider/operator · Compromised dependency.

## 3. Threats and mitigations

| ID         | Threat (STRIDE)                                           | Mitigation                                                                                                                         | Evidence                                                                                                                                                                         |
| ---------- | --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-SPOOF-1  | Forge a lease offline                                     | Ed25519 only; `alg` pinned; client holds public keys only; unknown `kid` rejected; payload edits break the signature               | JWS (tamper, alg=none, HS256 confusion, wrong key under same kid); SDK ("payload edited", "unknown or attacker key"); VEC                                                        |
| T-SPOOF-2  | Copy a lease to another machine                           | Lease bound to product, installation id and device-key thumbprint (`cnf.jkt`); refresh needs a signature by that key               | SDK (wrong product/installation/device); API ("lease file copied to another machine is useless"); LIC ("lease without the device key cannot be turned into a new lease")         |
| T-SPOOF-3  | Use a stolen license key without account                  | Activation needs session **and** org membership **and** device proof; non-member gets the same response as an unknown key          | LIC ("unknown key and … non-member are indistinguishable"); SEC ("stolen license key is useless", "key alone is not authority")                                                  |
| T-SPOOF-4  | Register someone else's public key                        | Proof of possession: signature over server nonce by the private key                                                                | LIC ("proof by a different key … no possession")                                                                                                                                 |
| T-SPOOF-5  | Guess license keys                                        | 125-bit random keys; HMAC-with-pepper lookup; uniform `invalid license` response; per-route rate limits                            | LIC (uniform errors); API (rate limits); `packages/crypto/test/secrets.test.ts`                                                                                                  |
| T-TAMP-1   | Edit plan/entitlements in the client                      | Entitlements come from the signed lease only                                                                                       | SDK; VEC                                                                                                                                                                         |
| T-TAMP-2   | Roll the clock back to extend a lease                     | Persisted high-water mark → `clock_anomaly`; skew tolerance bounded (≤ 1 h)                                                        | SDK ("clock rollback", "skew clamped"); VEC                                                                                                                                      |
| T-TAMP-3   | Alter audit history                                       | Hash chain; DB triggers reject UPDATE/DELETE/TRUNCATE; `verifyChain`                                                               | `packages/audit/test/audit-log.test.ts` (edit, delete, recomputed-hash forgery); DB ("append-only"); SEC (audit verify)                                                          |
| T-REPUD-1  | Operator denies an action                                 | Every operator mutation requires a reason and is audited with actor                                                                | LIC ("every operator mutation is audited"); SEC ("require a reason and are attributed")                                                                                          |
| T-INFO-1   | Cross-tenant read (IDOR)                                  | `orgId` on every repository call; composite FKs; unauthorized = 404 identical to nonexistent                                       | SEC (tenant isolation ×4, compares real vs ghost ids); LIC ("tenant isolation"); DB (cross-tenant FK rejections)                                                                 |
| T-INFO-2   | Secrets in logs/audit/telemetry                           | `redact()` on audit/signals; telemetry allow-list; logger redacts `authorization`; license key shown once                          | LIC ("never leaks the license key…"); API ("logs never contain bearer tokens, license keys, nonces or signatures"); `packages/telemetry/test`; `packages/audit/test` (redaction) |
| T-INFO-3   | Validation errors echo secrets                            | zod errors report paths/codes only                                                                                                 | API ("without echoing values")                                                                                                                                                   |
| T-INFO-4   | Account enumeration via login                             | Uniform error; one scrypt derivation even for unknown users                                                                        | `packages/auth/test/auth.test.ts` ("identical error"). Registration still reveals existing emails — see R-3                                                                      |
| T-DOS-1    | Challenge flooding                                        | TTL 5 min, per-installation outstanding cap, rate limit, 64 KB body limit                                                          | LIC ("caps outstanding challenges"); API (413 body limit; rate limit)                                                                                                            |
| T-DOS-2    | Race to exceed device limit                               | Transactional count+insert; idempotent re-activation                                                                               | LIC ("race-free: 20 concurrent … exactly 3"); DB ("FOR UPDATE … respects the device limit")                                                                                      |
| T-DOS-3    | Targeted account lockout                                  | **Accepted** — see R-9                                                                                                             | —                                                                                                                                                                                |
| T-EOP-1    | Escalate to org owner / operator                          | Server-side RBAC; grant ≤ own rank; strict schemas reject `platform_role`; operator re-verified per request                        | SEC (privilege escalation ×5); auth tests                                                                                                                                        |
| T-EOP-2    | Restart trials                                            | `trial_claims` unique per (product, org) and (product, user)                                                                       | LIC ("cannot be restarted — not by repeating, not via another org, not by another user"); DB ("trial history")                                                                   |
| T-REPLAY-1 | Replay activation/refresh                                 | Challenge single-use, purpose/installation/subject-bound, 5 min TTL, atomic consume                                                | LIC ("single use", "expires", "cannot be used for another purpose"); SEC ("replayed activation requests"); DB ("exactly one concurrent UPDATE wins")                             |
| T-REV-1    | Revoked license works offline                             | Residual — bounded by lease TTL; enforced at next online contact                                                                   | LIC ("revocation … enforced at the next online contact"); R-1                                                                                                                    |
| T-CANARY-1 | Probing with honeypot key                                 | Audited + high-severity signal; response identical to unknown key; never issues a lease; denied again by policy (defense in depth) | LIC ("canary licenses"); POL ("canary licenses are denied by policy itself"); SEC ("canary … looks exactly like an unknown key")                                                 |
| T-KEY-1    | Signing-key compromise                                    | Key lifecycle with `kid`; revoked keys leave the trust bundle immediately; refresh re-signs with the new key; signing fails closed | JWS (KeyRing lifecycle); LIC ("signing-key rotation", "fails closed"); SDK ("revoked signing key")                                                                               |
| T-CFG-1    | Misconfigured production (weak secrets, volatile storage) | Startup fails closed                                                                                                               | `services/platform-api/test/config.test.ts`                                                                                                                                      |
| T-SUPPLY-1 | Malicious dependency                                      | Lockfile; 4 runtime deps; `npm audit`, dependency review, secret scan, CodeQL in CI; no private keys in tree                       | `.github/workflows/*`, `tools/check-boundaries.mjs` (key-material scan). CI not yet run on GitHub — see R-11                                                                     |
| T-SUPPLY-2 | Signing code ships to clients                             | `sdk-core` may import only `@trust/crypto/verify`                                                                                  | `tools/check-boundaries.mjs` (run by `npm run lint`)                                                                                                                             |
| T-DATA-1   | Licensing failure destroys documents                      | The platform only returns states; no code path deletes user data; expired/invalid leases surface as degraded states                | SDK ("expired leases still return claims … no data loss path"); API ("degrades without destroying anything")                                                                     |

## 4. Residual risks (explicitly accepted for V1)

| ID   | Risk                                                                                                                                                                                                                                                           | Plan                                                                                                               |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| R-1  | A revoked/deactivated device keeps working until lease `exp` while offline                                                                                                                                                                                     | Tier-based TTLs (policy config); Milestone 2 adds risk-based short leases and revocation hints                     |
| R-2  | A cracked client binary can skip lease checks (client-side checks are defense in depth)                                                                                                                                                                        | Server-side value (cloud features, capability tokens) is the real boundary; Milestones 2–3 add integrity manifests |
| R-3  | Registration reveals whether an email is registered                                                                                                                                                                                                            | Email-verification flow (identity milestone) removes the oracle                                                    |
| R-4  | Bearer session tokens, single 12 h token, no refresh rotation, no MFA/passkeys                                                                                                                                                                                 | Identity milestone: short access + rotating refresh, passkeys for operators                                        |
| R-5  | Operators are a flat `platform_admin` role (no JIT elevation or dual control); mitigated by mandatory reasons, audit, per-request re-check                                                                                                                     | Milestone 6                                                                                                        |
| R-6  | Device key is software-held; no TPM / Secure Enclave / Keystore                                                                                                                                                                                                | Milestone 2 (`DeviceKey` seam exists)                                                                              |
| R-7  | Rate limiting and login lockout counters are per-process memory                                                                                                                                                                                                | Redis/edge limits when horizontally scaled                                                                         |
| R-8  | ~~No PostgreSQL adapters~~ **Resolved** (see ADR-005): durable adapters exist, are contract-tested against the in-memory reference and run the full behavioural suites. Remaining caveat: not yet load-tested; connection-pool sizing and failover are untuned | Load/soak test and pool tuning before launch                                                                       |
| R-9  | Login lockout is per email: an attacker can lock out a known victim for 15 min                                                                                                                                                                                 | Per-(email, IP-class) counters and step-up when edge limits exist                                                  |
| R-10 | Audit entries are still written in a separate transaction after the business change; a crash between them loses an audit entry. The PostgreSQL adapter makes same-transaction auditing possible but the services do not yet use it                             | Thread an audit writer through `LicensingRepo`/`AuthStore` transactions (next hardening step)                      |
| R-11 | CI workflows and the Dockerfile have **not been executed** on GitHub / Docker (no daemon here). Local equivalents were run: lint, types, tests, DB tests on PostgreSQL 16, clean `npm ci --omit=dev` start-up                                                  | First push to GitHub; pin actions by SHA once approved                                                             |
| R-12 | No SSRF, XSS, file-upload or CSRF surface exists in V1 (no outbound fetches, no HTML, no uploads, no cookie auth). These controls are required before such features ship                                                                                       | Revisit with Milestone 5 (workspace/cloud-drive) and the portal                                                    |
| R-13 | A database superuser can disable the audit-immutability triggers and rewrite history; `verifyChain` detects it only when run (proved by test), and a rewrite that recomputes the whole tail is undetectable without an external witness                        | Periodically publish the audit head hash to an external append-only store; alert on `verify` failure               |
| R-14 | Transactions use READ COMMITTED with explicit row locks. Lock ordering is license → activation everywhere, but a deadlock (SQLSTATE 40P01) would surface as a 500 rather than being retried                                                                    | Add bounded retry on 40001/40P01 at the `transaction()` boundary                                                   |
