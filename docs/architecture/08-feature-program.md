# Feature implementation program

## Source and limits

The requested scope is every intended feature. Inventory source: architecture/01-system-context.md, architecture/02-domain-model.md, architecture/05-v1-status-and-handoff.md, existing API and SDK. These refer to an original numbered brief that is not present in the checkout. Several later contexts have names but no behavioral specification. This inventory preserves those requirements rather than claiming that a prototype implements them.

## Current slice

Portal, operator console and device demo are implemented locally against existing API flows. Authenticated catalog browsing is added to the API. Chromium verification exercises account/team/provisioning/device workflows; application and PostgreSQL suites verify security boundaries. ResendMailDelivery and MemoryMailDelivery implement a tested delivery seam; PaddleWebhookVerifier validates original-byte HMAC signatures and timestamps. Email verification and password-reset endpoints are implemented, including durable token state and session revocation; they are enabled only when Resend sender/key/origin are configured. External sign-in remains pending. Billing is optional and disabled until the complete provider configuration is supplied. Authenticator MFA is implemented with encrypted secrets, single-use recovery codes, replay prevention, session revocation and optional operator enforcement (ADR-017). Passkeys are implemented (ADR-023): WebAuthn registration and passwordless sign-in with origin/RP binding, single-use challenges, user verification and signature-counter clone detection; attestation is not trusted. Durable encrypted delivery retry is implemented as an opt-in mode (ADR-020), with transactional enqueue, fenced worker claims, bounded retries and expiry/invalidation checks; it requires migration 0010, app grants and a separate encryption key. Monthly quota accounting is implemented (ADR-018): current plan/override limits, tenant-bound consumption, immutable receipts, replay protection and portal usage. Initial Paddle subscription checkout, durable intents, signed mapped payment/subscription notifications, ordered event receipts, uncertain-outcome reconciliation, portal/SDK methods and an isolated Paddle.js payment page are implemented (ADR-019). Plan-change checkout, replacement provider subscriptions, refunds and reconciliation automation remain pending. Capability tokens are implemented (ADR-024): device-proved, five-minute, audience-, device- and license-bound tokens for one resolved capability, verified offline by services with `verifyCapabilityToken`. Named-user seats and offline transfer are implemented (ADR-025): seat-based licenses require a seat to activate, admins assign seats under the license lock, and removing a seat or a device reports how long offline leases remain valid. Processing services themselves remain pending. Device trust is implemented (ADR-026): device passports, server-observed signals with 90-day retention, a deterministic posture (OBSERVE / STEP_UP_AUTH / RESTRICT) that never overrides license invariants, staged by DEVICE_POLICY=observe|enforce. Windows DPAPI storage and asynchronous native key providers are implemented; verified TPM attestation remains pending (passports report attestation as unknown). Signed update feeds, dual-threshold root rotation, rollback/expiry checks and integrity-checked artifact staging are implemented; production custody/hosting, evidence verification and platform installation/recovery remain prerequisites.

File sharing, document publication, short links and upload requests are implemented (ADR-021, [10-file-sharing-and-short-links](10-file-sharing-and-short-links.md)): resumable direct-to-storage uploads, quarantine, controlled share links (latest/fixed versions, password, expiry, limits, recipients, review), receipts, QR codes, retention jobs and separate usage meters. Watermarking, preview derivatives and submission bundles remain phase 3; the S3 adapter still needs a live-bucket check.

Privileged operations are implemented (ADR-022): dual-control requests that act as just-in-time grants bound to the requester, operation, target and reason; approval by a distinct operator with a fresh authenticator code; at-most-once execution; organization and platform freeze (lifting needs dual control); bounded break-glass witnessed by the external audit anchor. `PRIVILEGED_DUAL_CONTROL=true` puts license revocation under dual control (staged rollout). Quorums larger than two remain out of scope.

## Browser boundary

Same-origin static portal served by the existing API at `/`. No new frontend build dependency. External local script/style assets only; no inline script, eval, unsafe HTML insertion, or third-party assets. Bearer sessions stay in memory and are lost on reload. Existing API remains the authorization boundary; hidden UI controls never supply authorization. Display only API-returned data. Public HTML contains no tenant/private material. A separate-origin `/checkout` payment page permits Paddle CDN scripts and frames under its own CSP; this exception does not apply to the account portal. Sensitive one-time license keys are shown once and never persisted in browser storage. Mobile and keyboard interactions must remain usable.

## Infrastructure requirements

A local adapter is not evidence of email delivery, payment settlement, hardware attestation, immutable witnesses, or backup recovery in production. Provider choice and secure settings are required; never ask for credentials in chat. Deployment follows tested local work, not unverified feature stubs. Do not advertise planned advanced milestones as active product features.
